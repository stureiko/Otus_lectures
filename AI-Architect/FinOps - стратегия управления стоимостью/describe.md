📘 ЧАСТЬ 1. Теория (50–60 минут)

⸻

🟦 Слайд 1. О чём занятие (5 мин)

Ключевая мысль:

Архитектура без учета стоимости = технический долг + финансовый риск

Что разберем:
	•	Почему FinOps — это не про бухгалтерию
	•	Как архитектура напрямую влияет на стоимость
	•	Как снизить расходы без деградации качества

⸻

🟥 Слайд 2–3. Проблема: почему cloud bill выходит из-под контроля (10 мин)

Типовые причины:
	•	overprovisioning (ресурсы «с запасом»)
	•	забытые ресурсы (zombie instances)
	•	неэффективные ML pipeline
	•	неправильный storage tier

AI/ML специфика:
	•	GPU простаивают
	•	training запускается без контроля
	•	дублирование данных

Ключевая мысль:

Cloud по умолчанию оптимизирован под скорость, а не под стоимость

⸻

🟩 Слайд 4–6. Принципы FinOps (15 мин)

Основные принципы:
	1.	Visibility (прозрачность)
	2.	Accountability (ответственность)
	3.	Optimization (оптимизация)
	4.	Continuous improvement (итерации)

⸻

Важный сдвиг мышления:

Без FinOps	С FinOps
фикс бюджет	динамическая оптимизация
cost = проблема	cost = метрика
централизованный контроль	распределённая ответственность


⸻

Ключевая формула:

Cost = f(Architecture, Load, Efficiency)

⸻

🟨 Слайд 7–9. Роль архитектора (15 мин)

Главная идея:

Архитектор — главный драйвер стоимости

⸻

Где принимаются решения стоимости:
	1.	Compute
	•	CPU vs GPU
	•	batch vs streaming
	•	autoscaling
	2.	Storage
	•	hot vs cold
	•	S3 vs FS vs DB
	3.	Network
	•	межзонный трафик
	•	egress cost

⸻

Примеры архитектурных ошибок:
	•	хранение всего в hot storage
	•	постоянные GPU-инстансы
	•	отсутствие batching

⸻

🟪 Слайд 10–12. Стоимость AI/ML pipeline (15 мин)

Разбиваем pipeline:

Data → Feature → Training → Serving → Monitoring


⸻

Где «текут деньги»:

Этап	Типичные расходы
Data ingestion	storage + transfer
Feature engineering	compute
Training	GPU $$$
Serving	latency-driven overprovision
Monitoring	logging explosion


⸻

Пример:
	•	training = 70% cost
	•	serving = 20%
	•	остальное = 10%

⸻

Ключевая мысль:

Самые дорогие решения часто принимаются «по умолчанию»

⸻

🟫 Слайд 13–15. Инструменты и практики (10 мин)

Инструменты:
	•	AWS Cost Explorer / GCP Billing
	•	Kubernetes metrics (Prometheus)
	•	Kubecost
	•	MLflow (cost per experiment)

⸻

Практики:
	•	tagging (project / team / env)
	•	budgets + alerts
	•	rightsizing
	•	spot instances
	•	lifecycle policies

⸻

Важный принцип:

Если нет тегов — нет FinOps

🧪 ЧАСТЬ 2. Практика (30 минут)

⸻

🎯 Задача

Студенты получают упрощённый cloud bill + архитектуру AI-системы

⸻

Cloud bill (упрощённый):

Service	Cost/month
EC2 (GPU)	$12,000
S3	$3,500

Kubernetes nodes	$4,000
Logging	$1,500


⸻

Архитектура:
	•	training pipeline (ежедневно)
	•	realtime inference
	•	хранение данных в S3 (без lifecycle)
	•	Kubernetes без autoscaling

⸻

🧩 Задание (15 мин)

Найти:
	1.	3–5 главных источников затрат
	2.	архитектурные причины
	3.	предложить изменения

⸻

💡 Подсказки студентам:
	•	GPU используются 24/7?
	•	нужен ли realtime?
	•	можно ли batching?
	•	нужен ли hot storage?

⸻

🛠 Ожидаемые решения (разбор — 15 мин)

Типовые оптимизации:

⸻

1. GPU → Spot + scheduling

Экономия: до 60%

⸻

2. Training → batch + реже

Экономия: 20–40%

⸻

3. S3 lifecycle (hot → cold)

Экономия: 50–80% storage

⸻

4. Autoscaling в Kubernetes

Экономия: 30%

⸻

5. Logging reduction

Экономия: 20–50%

⸻

📊 Финальный результат

Студенты должны показать:

👉 как получить ≥20% экономии
