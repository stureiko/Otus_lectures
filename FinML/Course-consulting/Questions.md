# Вопросы

## 1. Есть ли практика использования моделей грубокого обучения в ансамбле построенном на основе средств sklearn. Можно ли построить стек в котором метамоделью будет нейросеть (к примеру CNN).

Можно, но sklearn довольно простые модли и не следует ожидать выского качества. Вместе с тем это довольно легкие модели и они легко учатся.

## 2. На сколько распространена практика использования синтетических данных при обучении глубоких сетей. Пример - CNN и сети с алгоритмами RL.

Да вполне. Но, есть ограничения

- Разрыв в распределениях (simulation-to-real gap) — поведение моделей в синтетике и в реальности может отличаться.
- Переобучение на синтетике, если она слишком однородная.
- Неочевидная проверка корректности — насколько синтетические данные отражают реальность?

## 3. Как на практике в пайплайнах работают с аномалиями данных. Верно ли, что аномалии классифицируют как инцидент и передают для обработки "на руки" для принятия решения об изменениях в конвеере обучения модели.
Как такие решения имплементируются? В конвеер добавляются стадии, которые нормализуют данные за указанный период или нет?

Методы принятия решения:

- Модель с Explainability (SHAP, LIME) показывает, что фича с аномалией влияет -> надо вмешаться
- Метрики качества/дрифта ухудшаются -> триггер на адаптацию пайплайна
- Повтор аномалий по расписанию -> сигнал

## 4. На сколько рационально строить модель не на базе ансамбля, а на базе иерархического обучения. Пример https://docs.agilerl.com/en/latest/tutorials/skills/index.html.
Здесь в качестве примера можно рассмотреть процесс определения тренда, где агенты учатся вычислять метрики (SMA, RSI и другие) и отдавать результат оркестратору.

Да, в случае таких задач, как определение тренда на рынке (или любой другой compositional task), построение иерархии агентов с распределением ролей может быть более интерпретируемым, адаптивным и устойчивым решением, чем просто ансамбль моделей.

Пример: иерархическое обучение тренду

Архитектура:

Low-level агенты:

- Agent 1: вычисляет SMA(5), SMA(20), выдает бинарный тренд +1/-1.
- Agent 2: оценивает RSI и помечает перекупленность/перепроданность.
- Agent 3: анализирует MACD crossover.
- Agent 4: находит свечные паттерны (Doji, Engulfing, и т.п.).

Все они обучаются независимо — или с teacher guidance (можно использовать Imitation Learning или Supervised RL).

High-level агент (оркестратор):

- Принимает сигналы агентов, и на их основе:
- Делает вывод о тренде (short/long/hold).
- Может “отключать” неинформативные агенты.
- Может дообучать агентов (meta-learning loop).

Зачем так делать?

- Модульность: вы можете легко заменить одного агента, не переобучая всю систему.
- Интерпретируемость: легко объяснить: “мы открыли лонг, потому что SMA показал рост, RSI — не перекуплен”.
- Адаптивность: при смене рынка (например, крипта → акции) можно заменить/добавить агентов.
- Метаподход: можно обучать high-level агента как reinforcement meta-agent, который учится выбирать агентов (как в AgileRL).

Недостатки

- Сложность конфигурации и обучения: нужно разрабатывать интерфейсы взаимодействия между агентами, определять цели, поощрения.
- Скорость обучения ниже, чем у ансамбля.
- Инженерная сложность: требует архитектуры и системы логирования для каждого агента и их взаимодействия.

## 6. Как реализовать риск-менеджмент (размер позиции/ордера) в торговом роботе? Нужна ли отдельная ML-модель (и как её обучать) или достаточно стандартных алгоритмов (типа % от баланса, ATR) – и насколько они эффективны?

Базовые (детерминированные) подходы
- Фиксированный % от капитала& Пример: риск на сделку не больше 1–2% капитала.
- ATR (Average True Range). Используется для адаптивного стоп-лосса и определения размера позиции.
- Kelly Criterion (реже).Оценивает долю капитала на сделку по ожидаемому выигрышу.
- Volatility scaling. Пропорциональное уменьшение размера позиции при росте волатильности.
- Max drawdown / max exposure. Ограничения на просадку или общий риск по всем позициям.

А нужны ли ML-модели для риск-менеджмента? Иногда да — но это редкость. 
Когда:
- Нужно адаптивно предсказывать волатильность / риск (в т.ч. VaR, CVaR).
- Вы хотите учиться на ошибках модели — обучить RL-агента принимать решения об открытии/закрытии с учётом убытков.
- Вы решаете комплексную задачу: “Не просто торговать, а управлять портфелем и перерешивать оптимизацию позиции каждый день”.

Подходы:
- Regression model for drawdown - Обучение на исторических данных: предсказывает вероятность убытка.
- Deep Reinforcement Learning (DRL) - Агент учится управлять позицией/левериджем, чтобы максимизировать reward = Sharpe ratio.
- Bayesian risk estimation - Оценка неопределенности в сигнале модели и адаптация размера позиции.

ATR-based sizing - Работает в волатильных рынках
Волатильностная шкала - Позволяет выдерживать серии просадок
ML-модель на риск - Хорошо работает только при качественной валидации и контроле переобучения
RL-модель (DRL-agent) - Потенциально лучший результат, но требует сложной настройки и симуляции

## 7. Как проектировать правила входа, избегая переоптимизации от слишком строгих условий (много индикаторов)? Эффективнее использовать диапазоны значений индикаторов или обучать модели на каждом индикаторе и комбинировать их с весами? Хочется услышать практические рекомендации, так как сейчас довольно часто сталкиваюсь со слишком строгими правилами входа в сделку по стратегии

Очень распространённая проблема

Рекомендации:
- Использовать диапазоны, а не точки. Например вместо 
```python 
RSI < 30
```
использовать 
```python 
signal_strength = 1 - (RSI - 20) / (40 - 20)
```
Так вы получаете мягкую функцию активации, которую можно комбинировать.

- Сигнальные функции вместо логики if
Превратите каждый индикатор в числовой сигнал (0–1), отражающий силу сигнала. 
```python
rsi_signal = max(0, min(1, (40 - RSI) / 20))  # от 1 (RSI=20) до 0 (RSI=40)
macd_signal = sigmoid(MACD_diff)
sma_signal = 1 if SMA_fast > SMA_slow else 0
```
и затем
```python
entry_score = w1 * rsi_signal + w2 * macd_signal + w3 * sma_signal
```
И вход в сделку, если entry_score > threshold.

- Обучайте веса сигнальных функций через RL-агента, который учится оптимально комбинировать сигналы, или с помощью бэйесовской оптимизации

- Контролируй метрики переобучения
  - Смотрите кол-во сделок на тесте: если < 30 — стратегия ненадёжна.
  - Метрики: PBO (Probability of Backtest Overfitting), Sharpe Stability, Drawdown Entropy — они сигнализируют переоптимизацию.
  
- Оптимизируй не правила, а распределение вероятности входа
```python
P(entry | features) > 0.8
```
