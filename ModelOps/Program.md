# Курс: ModelOps / MLOps для LLM-систем

Формат: лекции + практики + мини-лабы

Итог: end-to-end LLM-система, выкаченная в облако

Фокус: инженерный, production-first

## Блок 1. Foundations: ModelOps, MLOps и LLM-мышление (8 занятий)

Цель блока: сформировать у студентов правильную картину, что такое ModelOps, чем он отличается от ML-research, и почему LLM меняют правила игры.

### 1. Введение в ModelOps и MLOps

- Что такое ModelOps, MLOps, DevOps — и где границы
- Почему “обучить модель” ≠ “сделать продукт”
- Жизненный цикл ML-модели

#### Практика: «ML ≠ продукт»

Формат: разбор кейса + групповая работа

Студентам даётся описание: «Есть модель, обученная в ноутбуке, accuracy = 0.92»

Задание:

- перечислить, чего не хватает до продукта
- разложить путь: идея → обучение → прод → эксплуатация

Результат:

- схема жизненного цикла ML-модели
- список ролей (ML, DevOps, Data, Product)

Ключевой инсайт занятия: ModelOps начинается там, где заканчивается ноутбук.

### 2. Эволюция ML → DL → LLM → AI Systems

- От классических моделей к foundation models
- Почему LLM — это платформы, а не просто модели
- Новые роли: LLM Engineer, AI Platform Engineer

#### Практика: «Классификация систем по уровню зрелости»

Формат: архитектурный анализ

Даны 3–4 системы:

- классический ML (скоринг)
- DL (CV/NLP)
- LLM (чат-бот)
- LLM + инструменты

Задание:

- определить, к какому поколению относится система
- какие компоненты обязательны
- где появляется ModelOps

РРезультат: таблица «Тип системы → архитектура → риски → Ops»

### 3. Архитектура ML-систем

- Online vs Offline inference
- Batch / streaming / real-time
- Где возникает технический долг

#### Практика: «Выбор архитектуры под кейс»

Формат: мини-дизайн-сессия

Кейс на выбор:

- антифрод
- рекомендательная система
- чат поддержки

Задание:

- выбрать тип inference (batch / online)
- обосновать latency / SLA
- указать точки технического долга

Результат: простая архитектурная схема и список trade-offs

### 4. Особенности LLM-систем

- Prompt ≠ код, но ведёт себя как код
- Стоимость inference и latency
- Контекст, токены, ограничения моделей

#### Практика: «Prompt как артефакт системы»

Формат: hands-on + обсуждение

Даны несколько prompt’ов, нужно определить, какие из них:

- нестабильны
- плохо масштабируются
- опасны

Попробовать изменить prompt → зафиксировать версию → описать регрессию

Результат: версия prompt’а и список рисков prompt-based логики

### 5. Data-centric подход

- Почему данные важнее архитектуры
- Dataset versioning
- Train / eval / prod / data drift

#### Практика: «Где сломается модель?»

Формат: data thinking workshop

Описан ML/LLM сервис. Нужно:

- разделить данные на train / eval / prod
- придумать сценарии data drift
- определить, какой дрейф заметим первым

Результат: карта данных системы и чек-лист data quality

### 6. Метрики в ML и LLM

- Классические ML-метрики
- LLM-метрики: relevance, faithfulness, toxicity
- Offline vs online evaluation

#### Практика: «Метрики ≠ бизнес»

Формат: аналитический разбор

Даны метрики:

- accuracy, F1
- relevance, faithfulness

Задание: сопоставить метрики бизнес-целям и определить, какие метрики:

- offline
- online
- прокси

Дополнительно обсуждение: почему высокая accuracy может быть вредной

Результат: таблица «метрика → зачем → когда использовать»

### 7. Риски и ограничения LLM

- Hallucinations
- Prompt injection
- Leakage данных

#### Практика: «Атака на LLM»

Формат: controlled adversarial lab

Дано описание LLM-сервиса. Нужно:

- придумать prompt injection
- сценарий утечки данных
- некорректный tool call
- предложить меры защиты

Результат: threat model для LLM и список защитных механизмов

### 8. Обзор полного production-pipeline

- От идеи до облака
- Что именно студенты будут делать в курсе
- Демонстрация финальной архитектуры

#### Практика: «Собери ModelOps pipeline»

Формат: итоговая интеграционная практика блока

Задание - нарисовать end-to-end pipeline:

- данные
- эксперименты
- модель
- деплой
- мониторинг
- обязательно:
  - указать точки контроля качества
  - точки отката (rollback)

Результат: финальная архитектурная схема курса и понимание «куда мы идём дальше»

## Блок 2. Data & Experiments: основа ModelOps (9 занятий)

Цель блока:
научить управлять данными, экспериментами и воспроизводимостью — фундамент ModelOps.

### 9. Управление данными

- Типы данных в ML/LLM
- Raw / processed / features
- Data contracts

#### Практика: «Карта данных ML/LLM-системы»

Формат: data-architecture workshop

Дается кейс (например: RAG-сервис для внутренней документации)

Необходимо перечислить все типы данных:

- raw (документы, логи)
- processed
- features
- embeddings
- метаданные
- определить владельцев данных
- указать точки обновления

Результат: data map системы и таблица: тип данных -> источник -> формат -> обновление

Инсайт: Если вы не можете нарисовать карту данных — ModelOps ещё не начался.

### 10. Версионирование данных

- Dataset versioning
- Branching данных
- Dataset lineage

#### Практика: «Dataset — это git-репозиторий»

Формат: conceptual + design

Дан набор данных (логически)

Необходимо придумать схему версионирования:

- major / minor версии
- ветки (dev / experiment / prod)
- описать lineage:
  - откуда данные
  - какие трансформации

Отдельный вопрос: что делать, если данные удалили / изменили?

Результат схема dataset lineage и правила изменения датасетов

### 11. Feature engineering и Feature Store

- Что такое feature store
- Offline / online features
- Особенности для LLM (embeddings)

#### Практика: «Одна фича — два мира»

Формат: архитектурное проектирование

Дается несколько фич:

- user_activity_7d
- document_popularity
- embedding_vector

Необходимо определить:

- offline / online
- latency требования
- источник истины
- решить: нужна ли feature store?

Результат: таблица feature specification и решение: feature store нужен / не нужен и почему

### 12. Эксперименты и воспроизводимость

- Experiment tracking
- Почему “random seed” — не решение
- Артефакты обучения

#### Практика: «Почему эксперимент нельзя повторить»

Формат: forensic analysis

Описан эксперимент:

- модель
- параметры
- данные (частично)

Необходимо:

- найти все точки невоспроизводимости
- предложить, какие артефакты надо сохранять

Обсуждение: почему seed ≠ воспроизводимость

Результат: чек-лист reproducibility и список обязательных артефактов эксперимента

### 13. MLflow и аналоги

- Experiments
- Models
- Artifacts
- Model registry

#### Практика: «Проектируем experiment tracking»

Формат: system design

Необходимо определить структуру экспериментов:

- experiment name
- run
- tags
- params
- metrics
- решить, что отправлять в model registry

Сделать сравнение: MLflow vs alternatives (концептуально)

Результат: схема experiment tracking и политика продвижения модели в registry

### 14. Embeddings и векторные представления

- Как LLM “видят” текст
- Embedding models
- Размерности, similarity, distance

#### Практика: «Embeddings — это не magic»

Формат: hands-on + анализ

Дается небольшой текстовый датасет. Необходимо:

- получить embeddings
- посчитать similarity
- найти «странные» совпадения

Обсуждение:

- влияние размерности
- domain mismatch

Результат: таблица similarity и список наблюдений и проблем

### 15. Векторные базы данных

- Архитектура vector DB
- Индексация
- Trade-offs

#### Практика: «Выбор vector DB под задачу»

Формат: comparative design

Дан сценарии:

- маленький RAG
- корпоративный поиск
- real-time assistant

Задание выбрать тип vector DB и объяснить:

- индексацию
- latency
- стоимость

Вопрос на подумать: когда vector DB не нужна?

Результат: decision matrix и аргументированный выбор

### 16. Оценка качества retrieval

- Precision / recall для RAG
- Ground truth
- Eval-датасеты

#### Практика: «Хороший retrieval — это не accuracy»

Формат: evaluation workshop

Даны:

- queries
- retrieved chunks
- ground truth

Необходимо:

- посчитать precision / recall
- придумать edge cases
- понять, где retrieval ломается

Результат: таблица метрик и выводы по качеству retrieval

### 17. Mini-lab

- Подготовка датасета
- Embeddings

#### Практика: «Собери data & experiment pipeline»
